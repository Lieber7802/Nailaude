# AgentHub 多 Agent 协作平台 - 产品需求文档 (PRD)

> 版本：v1.1 | 更新日期：2026-05-20 | 目标：20 天比赛 MVP

---

## 一、产品定位

**一句话定位：**

> AgentHub 是一个以 IM 聊天为核心交互的多 Agent 协作工作台，让用户像使用飞书一样与多个 AI Agent 对话、协作、生成和预览产物。

**核心价值主张：**

- 统一入口：多个 Agent（代码生成、代码审查、文档撰写等）集中在一个聊天界面
- 协作能力：支持群聊中多 Agent 协作完成复杂任务
- 产物可视化：Agent 输出不仅是文字，而是可交互的产物卡片（代码、网页预览、Diff）
- 即时预览：生成的网页/代码可在平台内实时预览，所见即所得

**与竞品的差异：**

| 对比维度 | 普通 AI 聊天 | AgentHub |
|---------|------------|----------|
| Agent 数量 | 单一模型切换 | 多 Agent 多平台协作 |
| 交互方式 | 纯文本问答 | IM 式 + 产物卡片 |
| 产物展示 | Markdown 渲染 | iframe 实时预览 + Diff 视图 |
| 协作模式 | 无 | Orchestrator 自动分派 |
| 平台接入 | 单一后端 | 多平台适配器统一接入 |

## 二、用户角色

| 角色 | 描述 | 核心诉求 |
|------|------|---------|
| 开发者用户 | 比赛评委 / 使用平台进行 AI 协作开发的人 | 通过自然语言与 Agent 对话，快速生成代码/网页，预览效果，迭代修改 |
| 平台管理员 | 配置 Agent、管理系统的角色（MVP 阶段即开发者本人） | 接入新 Agent、配置 Persona、管理系统设置 |

> MVP 阶段只聚焦「开发者用户」角色，管理后台以配置文件 / 简单设置页代替。

## 三、核心场景

### 场景 1：单聊生成网页（Demo 核心路径）

```
用户 → 新建对话 → 选择 "CodeAgent"（基于火山方舟）
用户：帮我生成一个简洁的登录页面
CodeAgent：好的，我来为你生成...
[代码卡片：login.html + login.css]
[网页预览卡片：iframe 实时渲染]
用户：把按钮改成圆角蓝色
CodeAgent：已修改...
[Diff 卡片：显示变更]
[网页预览卡片：更新后效果]
```

### 场景 2：群聊多 Agent 协作（跨平台协作）

```
用户 → 新建群聊 → 添加 CodeAgent(火山方舟) + ReviewAgent(OpenAI)
用户：@CodeAgent 帮我生成一个 Todo List 页面，@ReviewAgent 检查代码质量
Orchestrator：收到，分派任务中...
  → CodeAgent（火山方舟）负责生成代码
  → ReviewAgent（OpenAI）负责代码审查
CodeAgent：[代码卡片] [网页预览卡片]
ReviewAgent：[审查报告卡片] 发现 3 个建议...
  [Diff 卡片：优化建议的代码修改]
Orchestrator：任务完成，汇总如下...
```

### 场景 3：多轮迭代修改

```
用户：（在已有对话中）把导航栏改成固定顶部
Agent：（基于上下文理解"导航栏"指代）
[Diff 卡片：position: fixed 修改]
[网页预览卡片：更新效果]
```

### 场景 4：自定义 Agent

```
用户 → Agent 管理 → 创建新 Agent
选择底层平台：火山方舟 / OpenAI
设置名称：PRD Agent
设置 System Prompt：你是一位资深产品经理...
设置能力标签：[文档, 需求分析]
用户 → 与 PRD Agent 对话
用户：帮我写一个社交 App 的需求文档
PRD Agent：[文档卡片：PRD.md 渲染]
```

## 四、多平台 Agent 接入方案

> **课题硬性要求：至少接入 2 个主流 Agent 平台。**

### 4.1 接入策略

```
┌─────────────────────────────────────────────────────────┐
│                  AgentHub 平台层                          │
│                                                         │
│  ┌───────────────────────────────────────────────────┐  │
│  │            统一 Agent Adapter 接口                  │  │
│  │   interface AgentProvider {                        │  │
│  │     id: string                                    │  │
│  │     name: string                                  │  │
│  │     platform: "volcano" | "openai" | "custom"     │  │
│  │     sendMessage(input): AsyncStream<AgentOutput>  │  │
│  │   }                                               │  │
│  └──────────┬──────────────┬──────────────┬─────────┘  │
│             │              │              │             │
│  ┌──────────▼───┐  ┌──────▼──────┐  ┌───▼──────────┐  │
│  │ 火山方舟     │  │  OpenAI     │  │  自定义       │  │
│  │ Adapter     │  │  Adapter    │  │  Adapter     │  │
│  │             │  │             │  │              │  │
│  │ - 豆包模型   │  │ - GPT-4    │  │ - 兼容OpenAI │  │
│  │ - DeepSeek  │  │ - GPT-4o   │  │   格式的任意  │  │
│  │ - 方舟其他   │  │ - (Codex)  │  │   第三方API   │  │
│  └─────────────┘  └────────────┘  └──────────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 4.2 平台接入明细

| 平台 | 优先级 | 用途 | 接入方式 |
|------|--------|------|---------|
| **火山方舟** | P0 | 主力平台，赛方提供 | 火山方舟 SDK / HTTP API |
| **OpenAI 兼容** | P0 | 第二平台，满足"至少2个"要求 | OpenAI SDK（兼容 DeepSeek/Moonshot 等） |
| 自定义 Agent | P1 | 用户自建 Agent | 复用已有 Adapter + 自定义 Prompt |

### 4.3 如何体现"多平台"差异

为了让评委清晰看到"多平台接入"能力，需要在产品中明确体现：

1. **Agent 卡片标识平台来源**：每个 Agent 显示其所属平台图标（火山方舟/OpenAI）
2. **新建 Agent 时选择平台**：自定义 Agent 需选择底层平台
3. **群聊中混用不同平台 Agent**：Demo 场景中展示跨平台 Agent 协作
4. **设置页展示已接入平台**：平台管理中列出所有已接入平台及其状态

### 4.4 预置 Agent 设计

| Agent 名称 | 底层平台 | Persona 角色 | 能力标签 |
|-----------|---------|-------------|---------|
| CodeAgent | 火山方舟 | 全栈开发工程师，擅长生成 HTML/CSS/JS/React 代码 | `代码生成` `前端` `全栈` |
| ReviewAgent | OpenAI | 资深代码审查专家，擅长发现代码问题并给出改进建议 | `代码审查` `最佳实践` |
| DocAgent | 火山方舟 | 技术文档写手，擅长撰写 PRD、技术文档、API 文档 | `文档` `需求分析` |
| DesignAgent | OpenAI | UI/UX 设计师，擅长页面布局建议和样式优化 | `设计` `UI` `CSS` |

> 通过将不同 Agent 绑定到不同平台，在 Demo 中自然展示跨平台调用能力。

## 五、用户流程

### 5.1 主流程（Happy Path）

```
┌─────────────────────────────────────────────────────┐
│             用户进入平台（简单登录页）                  │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│              查看会话列表（左栏）                      │
│   ├── 点击已有会话 → 进入聊天                         │
│   └── 新建对话 → 选择 Agent / 创建群聊                │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│              聊天交互（中栏）                          │
│   ├── 输入文本消息                                    │
│   ├── @ 指定 Agent                                   │
│   ├── 引用/回复历史消息                                │
│   └── 发送 → 等待 Agent 回复                          │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│            Agent 回复 + 产物展示                       │
│   ├── 文本回复（流式打字效果）                         │
│   ├── 代码卡片 → 点击展开编辑器                        │
│   ├── Diff 卡片 → 点击查看变更 / 一键应用              │
│   └── 网页预览卡片 → 点击全屏预览（右栏）              │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│            产物预览与操作（右栏）                       │
│   ├── iframe 实时预览网页                             │
│   ├── 代码编辑器（可二次编辑）                         │
│   ├── Diff 视图（并排对比）                           │
│   └── 版本切换                                       │
└─────────────────────────────────────────────────────┘
```

### 5.2 群聊协作流程

```
用户发送消息（含 @ 多个 Agent）
        │
        ▼
Orchestrator 接收消息
        │
        ├── 解析 @ 指令 / 分析意图
        ├── 拆分子任务
        ├── 依次或并行分派给对应 Agent（可跨平台）
        │
        ▼
各 Agent 依次回复（标识各自平台来源）
        │
        ├── Agent A (火山方舟) 输出代码
        ├── Agent B (OpenAI) 输出审查结果
        │
        ▼
Orchestrator 汇总结果
        │
        └── 在聊天流中展示汇总消息
```

## 八、交互细节设计

### 8.1 消息流交互

| 交互场景 | 交互细节 |
|---------|---------|
| Agent 正在回复 | 消息气泡内显示打字指示器（三个跳动的点），同时消息文本流式逐字显示 |
| 流式回复中 | 底部出现"Agent 正在输入..."状态条，用户可点击"停止生成" |
| 代码块识别 | Agent 回复中的 ```code``` 自动渲染为代码卡片组件，而非纯文本 |
| 产物卡片生成 | 代码生成完成后，自动追加网页预览卡片（带 0.3s 淡入动画） |
| 发送消息 | 消息从底部滑入（150ms ease-out），自动滚动到最新消息 |
| 长消息折叠 | 超过 20 行的文本消息默认折叠，显示"展开全部" |

### 8.2 产物卡片交互

| 卡片类型 | 聊天流内展示 | 点击行为 |
|---------|------------|---------|
| 代码卡片 | 显示文件名 + 前 5 行代码预览 + 行数 | 点击 → 右栏打开完整代码编辑器 |
| 网页预览卡片 | 200px 高度缩略图（iframe 缩放） | 点击 → 右栏展开完整预览 |
| Diff 卡片 | 显示"N 行新增，M 行删除"摘要 + 前 3 行 Diff | 点击 → 右栏打开完整 Diff 视图 |

### 8.3 右栏预览面板交互

| 操作 | 行为 |
|------|------|
| 面板展开 | 首次点击产物卡片时，右栏从右侧滑入（300ms），宽度占 40% |
| 面板关闭 | 点击关闭按钮或无活跃产物时，右栏收起 |
| Tab 切换 | 预览/代码/Diff 三个 Tab 切换，保持各自滚动位置 |
| 全屏预览 | 点击全屏按钮，预览区域覆盖整个中栏+右栏 |
| 拖拽调整 | 左右栏之间可拖拽分隔线调整宽度 |
| 代码编辑 | 在代码 Tab 中修改后，预览 Tab 自动热更新（无需手动刷新） |

### 8.4 加载状态设计

| 场景 | 加载态 |
|------|--------|
| 页面首次加载 | 骨架屏（Skeleton）：左栏会话列表占位 + 中栏消息占位 |
| 会话切换 | 中栏消息区显示 Spinner (< 500ms)，超时显示骨架屏 |
| Agent 调用中 | 消息流底部显示 Agent 头像 + "正在思考..." + 跳动点动画 |
| 网页预览加载 | iframe 区域显示加载进度条，加载完成后淡入 |
| Agent 调用失败 | 红色错误提示气泡 + [重试] 按钮 |

### 8.5 空状态设计

| 场景 | 空状态内容 |
|------|-----------|
| 无会话 | 插图 + "还没有对话，点击下方按钮开始与 Agent 交流吧" + [新建对话] 按钮 |
| 新对话无消息 | 显示当前 Agent 介绍卡 + 3 个快捷提问建议（如"帮我生成一个登录页"） |
| 右栏无预览 | 浅色提示"点击聊天中的产物卡片，在此预览" |
| 搜索无结果 | "未找到相关会话" |

### 8.6 快捷操作

| 操作 | 触发方式 | 行为 |
|------|---------|------|
| @ 提及 | 输入框键入 `@` | 弹出 Agent 选择浮层，键盘上下选择，回车确认 |
| 复制代码 | 悬停代码卡片 | 右上角出现"复制"图标按钮 |
| 重新生成 | 悬停 Agent 消息 | 出现"🔄 重新生成"按钮 |
| 引用回复 | 悬停任意消息 | 出现"↩ 引用"按钮，点击后输入框上方显示引用预览 |

## 十、数据模型（核心实体）

```
User

├── username: string
├── avatar: string
├── created_at: datetime

Agent
├── id: UUID
├── name: string
├── avatar: string
├── description: string
├── system_prompt: text

├── platform: enum("volcano", "openai", "custom")   // ← 关键：标识所属平台

├── created_at: datetime

├── id: string ("volcano" | "openai" | ...)
├── name: string
├── icon: string
├── api_base_url: string
├── api_key: string (加密存储)
├── status: enum("connected", "disconnected", "error")
├── models: string[]                // 该平台可用模型列表

Conversation
├── id: UUID
├── title: string
├── type: enum("single", "group")
├── participants: Agent[]           // 参与的 Agent（可跨平台）
├── created_by: UUID (FK → User)
├── created_at: datetime
├── updated_at: datetime

Message
├── id: UUID
├── conversation_id: UUID (FK → Conversation)
├── role: enum("user", "agent", "system", "orchestrator")
├── agent_id: UUID (FK → Agent, nullable)
├── content: text                   // 消息文本内容
├── content_type: enum("text", "code", "mixed")
├── artifacts: Artifact[]           // 关联的产物
├── parent_message_id: UUID (nullable, 引用回复)
├── metadata: JSON                  // 扩展信息（token 用量等）
├── created_at: datetime

Artifact（产物）
├── id: UUID
├── message_id: UUID (FK → Message)
├── type: enum("code", "webpage", "diff", "document")
├── title: string                   // 产物标题（如文件名）
├── files: JSON[]                   // [{filename, content, language}]
├── diff_data: JSON (nullable)      // Diff 专用：{hunks, additions, deletions}
├── version: integer                // 版本号
├── previous_version_id: UUID (nullable)
├── preview_url: string (nullable)  // 预览地址
├── created_at: datetime
```

## 十五、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 火山方舟 API 延迟到账 | 平台1无法联调 | 前期用 Mock 开发；OpenAI Adapter 先行；Adapter 接口抽象好 |
